# STSサーボ管理・同期動作

GUIの **3 診断 → STS管理** で、CCTLのFDCAN2経由でSerialSVMDを操作する。
SWCTLはMCU側、基板アドレスは0。接続・設定照合の完了後に使用する。
[電源・IDの基本設定](sts3215_bringup.md)も参照。

## 操作モード

| モード | 指令値 | 動作 |
|---|---|---|
| 0・通常位置 | 0〜4095 | 絶対位置へ移動し保持。設定済み角度範囲内に限定 |
| 0・多回転位置 | −28672〜28672 | 最小・最大角度が両方0の場合の絶対位置。電源断で回転数を失う |
| 1・速度 | −1000〜1000 count/s | 符号が回転方向。GUIでは押している間だけ出力 |
| 3・相対ステップ | −28672〜28672 count | 現在位置から指定量を1回移動。最小・最大角度は両方0 |

実行前にサーボ内のモードと目標のモードを照合する。モード変更は内部設定で明示的に行う。
位置指令のspeedは0〜1000、加速度は0〜254。速度0の意味はサーボのモードに依存するため、
位置操作の停止には「停止・出力解除」を使う。
多回転の現在位置は12bitの単回転位置だけでなく符号付き値として表示する。
モード2（開ループ出力）は扱わない。

## ID・内部設定

探索は指定範囲を1台ずつPINGする。無応答のIDを飛ばし、応答したIDを表示する。
書込み可能項目はID、baud、モード、角度上下限、位置P/I/D係数、デッドバンド、
位置オフセット、加速度。保存設定はトルクOFF・ロック解除・書込み・読戻し・再ロックを行う。
FWは上記の許可リスト以外への書込みを拒否する。

設定変更時はバスに1台だけ接続し、GUIの確認欄をチェックする。
モード3への変更は角度上下限も0へ変更する。通常位置へ戻す際はモード0と角度範囲を設定し直す。
ID/baudの変更成功時はhostの対応する適用中設定も更新し、未保存状態にする。
調整画面で適用中の設定を読み直して保存する。複数台を戻す前にbaudを全台で揃える。
再通電後に再度読取り、保存状態を確認する。途中失敗した場合は新旧ID/baudを確認する。

## 同期移動と停止

「サーボ追加」で最大16台の目標を作る。全対象のモードと指令を確認し、必要な個体を
現在位置または速度0で有効化した後、1つのSYNC_WRITEパケットで目標を送る。
SYNC_WRITEは同じパケットで複数台へ指示する方式で、機構が同時刻に到着する保証ではない。
送信後は各個体の目標レジスタを読戻す。失敗時は全管理対象へのトルクOFFを試みる。

位置・相対ステップは明示停止まで保持。速度を含む単発操作は更新が150ms途切れるとhostが停止する。
通常操縦・個別テスト・設定適用とは排他。タブ移動、Space、`s`、CLIのstopで操作を中断する。
FW側にも通信Watchdogがあり、通信断中のトルクOFF到達は保証されない。

## シーケンス

同期目標をステップへ追加し、待機時間（100〜60000ms）を設定する。最大64ステップ・全体16台。
各ステップの指令確認後に待機し、次へ進む。待機は時間指定で、到達センサによる判定ではない。
そのステップに含めないIDは前の指令を維持するため、速度出力を終えるステップには速度0を指定する。
全ステップ終了時はトルクをOFFにする。途中停止後の自動再開は行わない。
シーケンスはTOMLとして保存・読込できる。ボーナスの機構寸法や角度は各目標に設定する。

## 監視

位置、速度、負荷、電圧、温度、電流、movingを取得する。目標IDを順に巡回し、
直近最大1200サンプルを保持する。画面でIDと項目を選んで時系列グラフを見る。
電流はメーカー資料に従い6.5mA/countで換算し、APIにはraw値も残す。
位置/速度はbit15、負荷はbit10の符号付き絶対値表現を復号する。
約100ms以上の間隔で1台ずつ取得するため、対象が増えると各個体の更新周期は長くなる。
最終受信からの経過時間を表示し、受信停止した値を最新の実測と見なさない。

## CLI / API

GUIと同じローカルAPIの`sts`アクションへTOMLを渡す。CLI操作権の取得方法は既存hostctlと同じ。

```sh
host/target/debug/hostctl sts --token "$TOKEN" --text 'operation="scan"
first=1
last=20'
host/target/debug/hostctl sts --token "$TOKEN" --file my_sequence.toml
host/target/debug/hostctl status
host/target/debug/hostctl stop
```

`status`の`sts`に処理状況・検出ID・計測サンプルを返す。受付成功と基板での実行確認は別。
速度moveは`--seconds 3`などを指定すると更新を継続し、最後に停止する。
APIで直接操作するときは`operation="renew"`を150ms未満の間隔で送る。
相対ステップのmove自体を繰り返して更新しない。

シーケンスファイルの形式例（角度は実機に合わせて編集する）：

```toml
operation = "sequence"
[[steps]]
wait_ms = 1000
[[steps.targets]]
id = 1
mode = 0
value = 2048
speed = 100
acceleration = 20
```

他の操作は`read`（id,address,width）、`configure`（id,address,width,value,single_servo）、
`monitor`（ids配列）、`move`（targets配列）。widthは1または2byte。

## CAN拡張仕様

標準ID0x320へ8byte。byte0=1、byte1=op、byte2=id、byte3=tag、byte4〜7=引数。

| op | 意味 | 引数byte4〜7 |
|---|---|---|
| 20 | レジスタ読取り | address,width,0,0 |
| 21 | 設定書込み | address,width,value_hi,value_lo |
| 22 | 同期目標をステージ | position_hi,position_lo,speed_hi,speed_lo。byte3は加速度 |
| 23 | 同期実行 | 0,0,0,0。byte2はステージ台数 |
| 24 | 計測取得 | 0,0,0,0 |
| 25 | PING | 0,0,0,0 |
| 27 | ステージ破棄 | 0,0,0,0 |

応答0x326は`[1,op,id,tag,result,data0,data1,error]`。読取り値はdata0が下位byte。
設定書込みではdata0=address、data1=値の下位byte。
計測0x327は`[1,id,tag,part,4byteのデータ]`で、レジスタ56〜70の15byteをpart0〜3で送る。
最後の未使用byteは0。計測本体が送信済みになるまで完了応答を待たせる。
hostはop/id/tagを照合し、部分フレームの欠落・timeoutで操作を中断する。移動指令は自動再送しない。
FWも新たなステージがない同一tagのEXECUTE再送では移動を繰り返さない。

## 検証と資料

シミュレータではID1・2・3を用意する。`host --simulate`で同じGUI/APIを検証できる。
シミュレータは通信と状態遷移の検証用で、負荷・電源・実際の運動応答を再現しない。
実機へのFW書込み、再通電後の設定保持、多回転の座標、負荷時の動作は別途確認する。

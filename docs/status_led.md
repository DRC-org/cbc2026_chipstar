# 状態表示LEDの規約

基板の状態を、離れた場所からでも読み取れるようにするための取り決め。

## 考え方

「このLEDが点いていたら○○」という割当は使わない。どのLEDが何番かを覚えていないと
読めず、数メートル離れると位置の判別自体ができないためである。

代わりに、**点灯位置ではなく動き方と速さ**で状態を表す。LEDの数が違う基板でも
同じ見え方になるようにしてあり、1個の基板でも6個の基板でも同じ状態は同じリズムで
光る。競技中に機体を見て状態が分かることを優先する。

## パターン

| 状態 | 点け方 | 意味 |
|---|---|---|
| **Boot** | 1灯ずつ順に流れ、消灯で一拍おく | 電源は入っているが、hostとの確立前 |
| **Safe** | 全灯をゆっくり点滅（1Hz、50%） | 待機。出力は無効 |
| **Run** | 全灯を常時点灯 | 動作中 |
| **Stop** | 全灯を速く点滅（4Hz、50%） | 停止した |
| **Error** | 全灯を短く2回点滅して休む | 異常。原因は通信で確認する |

見分けの要点。

- **点いているか / 動いているか** — Runだけが動かない。遠くからでも一目で分かる
- **速さ** — SafeとStopは同じ「点滅」だが4倍違う。並べなくても区別できる
- **リズム** — Errorは2回光って長く休む。等間隔の点滅と混同しない
- **流れ** — Bootだけが位置を移動する。まだ繋がっていないことが分かる

LEDが1個の基板では「流れ」が表現できないため、Bootは短い点灯と長い休みになる。
点灯している割合がSafe・Stopの50%と違うので区別できる。

## 基板ごとのLED

| 基板 | 個数 | 位置 |
|---|---|---|
| cctl | 3 | LED1〜3（PC1, PC2, PC3） |
| serial_svmd | 6 | LED1〜6（PA3, PA2, PA1, PA0, PF1, PF0） |
| DCMD | 1 | PA15 |
| svmd | 1 | UNO R4 の内蔵LED |

serial_svmdはLEDの番号とポート順が逆向きなので、点灯順が基板上の並びと一致するよう
`app.cpp` 側で対応付けている。

## 状態の決め方

異常を最優先とし、以下の順に判定する。

| 基板 | Error | Boot | Run / Stop / Safe |
|---|---|---|---|
| cctl | いずれかのslotの`err`が非0 | `HELLO`未受理 | 動作モード |
| serial_svmd | CAN未開始 | `HELLO`未受理 | 動作モード |
| DCMD | CAN未開始、または通信断で停止 | — | 動作モード |
| svmd | Watchdog超過 | 最初の指令を受ける前 | 有効チャネルの有無 |

DCMDは「通信断で止まった」場合をErrorとし、指令で止めたStopと区別する。
配線が抜けたのか操作で止めたのかが、機体を見るだけで分かる。

## 実装

判定は各FWの `domain/status_led.hpp` にあり、4基板とも同一の内容を持つ。
FW間で実装をリンクせず、仕様と `tests/status_led_test.cpp` を共有する方針に従う。

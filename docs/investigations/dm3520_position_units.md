# DM3520 / z軸の位置単位調査

## 結論

GT2・36Tプーリの送りは出力軸1回転あたり72 mmで正しい。
一方、実機の通信位置と物理移動の対応は未確定である。
現在の `native_per_unit = 1.1730445` は目測比による暫定値で、校正済みではない。
この調査では制御コード・実機パラメータを変更していない。

メーカーの機種別マニュアルは位置と速度を減速後の出力軸単位と定義する。
保存ログと移動量の観察はその定義だけでは説明できない。
減速前の回転角という仮説は候補だが、電気角として極対数7を掛ける根拠は確認できなかった。
通信の復号計算が正しいことと、通信値の物理単位が正しいことは別の検証である。

## 機械から確定できる値

`native_per_unit` は1 mmに対応する通信位置の増分。
減速比は `3591/187 = 19.203208556150`、極対数は7。
電気角は、モータの減速前の機械角に極対数を掛けた角度を指す。

| 通信位置の仮説 | 1 mmあたりの通信位置 | 20 mm移動時の通信位置差 |
|---|---:|---:|
| 出力軸rad（マニュアルの定義） | 0.087266462600 | 1.745329252 |
| 減速前の機械角rad | 1.675796081260 | 33.515921625 |
| 減速前の電気角rad | 11.730572568819 | 234.611451376 |

基本式は `2π/(36×2)`。下2行はこれに減速比、さらに極対数を掛けたもの。
実機の減速比レジスタ値 `19.203210830688477` と理論値の差は約0.000012%で、
大きな倍率差の原因にはならない。

旧換算値11.730445で物理的に10 mm動かした場合、各仮説でのGUI表示差は
順に0.0744、1.4286、10.0001 mmとなる。
「約10 mmに対して約1 mm」という目測は減速前角度と矛盾しないが、精密測定ではない。
またPMAXを256から2048へ8倍にした変更と換算変更が重なっており、
その時点の生データと実機設定を同時記録していないため、倍率の原因を一意に決められない。

## コードと数値の検証

- `cctl/src/domain/dm_codec.cpp` は位置応答の16 bit値を±PMAXへ線形変換する。
  PMAXが12.5、256、2048の各場合について全65,536値をメーカーSDKの式と比較した。
  最大絶対差はそれぞれ `9.54e-7`、`1.53e-5`、`1.22e-4`。
  浮動小数点の丸め範囲であり、倍率7・10・19.2の誤差ではない。
- 位置・速度指令はfloat値をそのままリトルエンディアンの8 byteに格納する。
  既知のIEEE754値による照合も通過した。追加の極対数・減速比演算はない。
- hostの位置表示は `(measured - origin) / native_per_unit`。
  GUIは目標位置ではなく測定位置を表示する。別の10倍変換はない。
- DMのインスタンスは1つで、PMAX変更時に復号範囲も更新する。
  CAN ID変更で範囲が初期値へ戻る経路は見つからなかった。

再実行（リポジトリルート、C++17コンパイラとPython 3が必要）:

```sh
c++ -std=c++17 -O2 -I cctl/src docs/investigations/dm3520_codec_audit.cpp cctl/src/domain/dm_codec.cpp -o /home/kotek/dm3520_codec_audit
/home/kotek/dm3520_codec_audit

```

## 速度上限のログに残る不整合

保存記録 `origin-resume-low-cap.json` には、CCTLへの `PARAM 14 0.02500` の
送信・応答確認がある。その間のRUN状態25点を重複除去したものが
[dm3520_low_cap.csv](dm3520_low_cap.csv)。位置は2.730から3.282へ変化し、目標はほぼ2.735で一定。

| 区間 | 基板時刻による位置変化率 | 指定上限0.025に対する比 |
|---|---:|---:|
| 全25点、1.2秒 | 0.493538462 | 19.741538462 |
| 最初3点・最後2点を除く20点 | 0.511774436 | 20.470977444 |

位置変化率は最小二乗直線の傾き。区間に依存しており、比が減速比と正確に一致したわけではない。
後者は `256/12.5 = 20.48` にも近く、数値の近さだけでは原因を特定できない。
hostが初めて各行を観測した時刻で計算すると全区間0.480366746、内部区間0.511064236になる。
host時刻にはまとめ受信の影響があるため、都合のよい区間や時刻だけを採用しない。

この試験の速度応答は主に生値0x7ff。
VMAX=200の場合、速度の1段階は約0.09768であり、0.025の実速度を分解できない。
指定値は速度上限であり実速度の計測値ではない。
負荷・過渡応答・モードの解釈もあるため、このログだけで角度単位は確定しない。

`ActuatorController::setJog` は `DmPosVelLimit` を位置目標の毎秒変化量の上限に使い、
送信処理は同じ数値をDMの位置速度モードの速度上限に渡す。
両者の単位が同じことを前提とする実装で、単位差が確認された場合は分離が必要。
現在の上限1.0と換算1.1730445では、CCTL内の目標変化率は表示換算で最大約0.852 mm/s。
通常速度5 mm/sを設定してもここで制限される。
これはソフトウェア上の目標速度であり、検証済みの物理速度ではない。
手で動かした際の表示倍率差は、この速度制限やPID調整だけでは直らない。

## 原点喪失で判明したこととの区別

以前の停止中のレジスタ80（p_m）は約-221.747だったが、通常応答はPMAX=12.5で約3.256と復号された。
25周期で折り返すと約3.253となる。実機と復号側のPMAXを500にすると約-221.767となり、
レジスタ値に近づいた。位置表現範囲を広げて再開時の不連続を防ぐ修正にはこの根拠がある。
これは累積座標の表現範囲の問題を示すが、その座標が物理的な何radなのかは証明しない。

現設定はPMAX=2048、位置範囲±2048。実機への書込み・読戻し・保存ACKは記録されているが、
電源再投入後の保持と手動移動中の値をまとめて確認した記録はない。
レジスタ81（xout）は保存ログで0。名称だけから減速前後の関係を決められない。

## メーカー資料の照合

以下は取得した版を固定した一次資料。資料上の仕様と実機での確認は区別する。

- [DM-S3519-1EC機種別資料](https://github.com/dmBots/DM-S3519-1EC/tree/372bd0b5c4db577c7766c8c0ba1b7d371a9cac85/manual)：
  中国語V1.1は位置・速度とも減速後と明記。減速比3591/187、極対数7。
  位置速度モードの例は説明の速度10 rad/sに対してbyte列が40.0で、例示に誤記がある。
  この誤記だけで位置単位の定義まで誤りとする根拠にはならない。
- [公式SDK](https://github.com/dmBots/motor-sdk/tree/0b2ede457bdbf0882e29ab9958ab8fda047b7f4a)：
  Python u2can例のパケット処理とCCTLを照合した。汎用実装であり、DM3520固有の単位を証明するものではない。
- [公式調整ツール](https://github.com/dmBots/motor-debugging-tool/tree/e8a2b1b93c9fbe84745b14056efa2ea41514a25c)：
  Linux arm64版v2.1.8.1の静的解析では通常位置の復号経路に減速比・極対数変換は見つからなかった。
  エンコーダ比較処理は80と81を読み差と一定オフセットを扱うが、機種固有の意味は確定できない。
- [公式FW](https://github.com/dmBots/motor-firmware/tree/267911465a403ccc4aceac890fe21d855b9a3c91)：
  DM3520向け6616_02があり、実機で読んだ版と対応する名称。
  公開バイナリから内部の角度計算は確認できなかった。
  共通のV17更新記録には設定通信と制御通信の混在時の応答不具合修正があるが、
  DM3520への適用性や今回の倍率差との関係は未確認。他機種FWを代用する根拠はない。

## 次の識別試験

1. 出力停止を保ち、PMAX・Gr・NPP・FW版を読み、CCTLの復号範囲と一致させて記録する。
2. 同じ設定のまま位置Aで通常応答の生16 bit値とレジスタ80を取得する。
3. 可動域内でベルトの10歯分（GT2なので20 mm）など、明確な距離だけ手動移動する。
   位置Bでも同じデータを取得する。設定書込みや原点変更を挟まない。
4. 生値から求めた差とレジスタ80の差を比較し、上の3候補と照合する。
   両者が合わなければPMAX・応答の解釈を先に調べる。どの理論値にも合わなければ
   センサ・ドライバ設定を調べ、目測倍率を換算値へ採用しない。
5. 位置単位を確定した後、速度指令と位置変化率の単位を独立に検証する。

この試験は理論式の選択を目的とする。係数の微調整や無負荷回転を要する校正とは別で、
Gr・NPPの変更やセンサ再校正は必要条件ではない。

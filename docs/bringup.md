# cctl 立ち上げ手順

実機に書き込んでから動かすまでの手順と、現場で使える操作をまとめる。

書き込み直後の機体は **動かない状態から始まる**。1 軸ずつ確かめながら有効にしていく。

## 起動時の状態

`setup()` は各モータのモード設定と原点取りまでを行い、トルクは入れない。
その後 DIP1 を読んで起動状態を決める。

| DIP1 | 起動状態 |
|---|---|
| OFF（既定） | **SAFE**。指令もトルクも入らない |
| ON | RUN。全軸を有効にして起動する |

DIP スイッチはプルアップ入力で、ON で LOW になる。何も設定していなければ OFF に
読めるので、**触っていない基板は動かない**。競技時のように電源投入だけで動かしたい
場合に DIP1 を ON にする。

## LED の読み方

端末を見られない位置からでも状態が分かるようにしてある。

| 表示 | 意味 |
|---|---|
| LED1 が 1Hz で点滅 | SAFE。指令待ち |
| LED1〜3 が点灯 | RUN。点灯しているものが有効な軸（LED1=r, LED2=θ, LED3=z） |
| LED1〜3 が 5Hz で点滅 | STOP。トルクを切っている |

## 操作

USB CDC の同じ 1 本のリンクで、指令の送信・テレメトリの受信・コントローラ入力の
送信をすべて行う。テキスト行なので、host の GUI がなくても
`screen /dev/ttyACM0 115200` のような端末だけで操作・観測できる。

### 指令

大文字小文字は問わない。前後の空白は無視する。

| 指令 | 動作 |
|---|---|
| `STOP` | 全軸のトルクを切る |
| `RUN` | 通常運転へ移る |
| `SAFE` | 待機状態へ戻す |
| `EN <軸> <0\|1>` | 軸ごとの有効・無効。軸は `R` `T` `Z` の組み合わせ（例 `EN T 1`, `EN RZ 0`） |
| `HOME` | 現在位置を原点に取り直し、目標値を 0 に戻す |
| `TEST <0\|1>` | 内蔵テストシーケンスの切替。RUN のときだけ動く |

打ち間違えた行は黙って捨てられる。`STOP NOW` のように余分な語が付いた行も
実行されない。

### テレメトリ

50ms ごとに 1 行送られてくる。

```
ST t=12345 r=12.300/11.800 th=45.000/44.200 z=100.000/99.100 en=7 mode=RUN err=00
```

| 項目 | 内容 |
|---|---|
| `t` | 起動からの経過 [ms] |
| `r` `th` `z` | 各軸の `目標/実測`。r と z は mm、th は deg |
| `en` | 有効な軸のビットマスク（1=r, 2=θ, 4=z） |
| `mode` | `SAFE` / `RUN` / `STOP` |
| `err` | z 軸ドライバのエラービット（16 進） |

値が `nan` で出た場合は制御が発散している。0 に丸めずそのまま出すようにしてある
ので、見落とさずに `STOP` を送ること。

host の GUI では「ステータス」画面に目標・実測・誤差の表として出る。

## 立ち上げの順序

1. **DIP1 を OFF にして書き込む。** LED1 が点滅していれば SAFE で待機している。
2. **テレメトリが流れていることを確認する。** 流れていなければ USB の接続か
   `MX_USB_Device_Init` までの初期化を疑う。この時点ではまだ何も動かない。
3. **軸を 1 つだけ有効にする。** 例えば θ だけなら `EN T 1` の後に `RUN`。
   他の 2 軸はトルクが入らない。
4. **実測値が動くか見る。** 目標を動かす前に、手で軸を動かして実測値が追随するかを
   確認する。ここで符号が逆なら `robot_config.hpp` の `*_SIGN` を直す。
   換算係数がずれていれば `*_MM_PER_OUTPUT_REV` や歯数を直す。
5. **目標値を与える。** コントローラの左スティックで r と θ が動く。
   暴れたら `STOP`。
6. **次の軸へ。** `EN T 0` で切ってから次の軸を有効にする。
7. 3 軸が個別に動いたら、`EN RTZ 1` でまとめて確認する。

## 調整値の反映

**PID ゲインと機械定数は、現時点ではコンパイル時定数のまま**で、変更には
ビルドと書き込みが必要になる。対象は `cctl/src/robot_config.hpp` で、
実測待ちの値には TODO を付けてある。

| 調整するもの | 場所 |
|---|---|
| θ のカスケード PID | `config::m3508` |
| 直動の換算係数・可動域・向き | `config::mech` |
| DM のマッピング範囲 | `config::dm` |
| EL05 の速度・電流リミット | `config::el05` |
| 制御周期 | `config::period` |
| 手動操作の速度・不感帯 | `config::manual_control` |

書き込み直すと θ の原点は初回フィードバックで取り直され、r は `setZero()` が
走る。ゲインを触るたびに原点が動く点に注意する。

換算係数を直したら、ホスト側のテストで往復が合うことを確認できる。

```sh
cd tests && cmake --build --preset default && ctest --preset default
```

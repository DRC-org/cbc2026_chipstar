# 汎用ファームウェア設計

基板ファームウェアは、基板に実装されたデバイスを安全かつ一定周期で動かすための
汎用実行基盤とする。機体の構成、軸の意味、入力割当、動作シーケンスは `host/` が
受け持つ。

## 責務の境界

ファームウェアに残すもの:

- CAN、UART、PWM、USB CDC と各モータのプロトコル
- 高周期の位置・速度・電流制御
- デバイスの速度・電流・温度など、機体座標によらない保護上限
- 指令値の検証、通信 Watchdog、SAFE / RUN / STOP
- 接点入力の読取りと10msのデバウンス、状態の報告
- デバイスの能力、状態、異常の通知

host に置くもの:

- `r`、`theta`、`z` など機体上の軸名と座標系
- 減速比、送り量、機体上の可動域
- コントローラ入力から目標値への変換
- 起動、原点出し、調整、競技動作のシーケンス
- 機体座標での速度・位置制限
- どの接点をどの機構のリミットとして使うかの割当、極性、到達時の扱い
- 原点出しの手順と、原点が決まるまでの運用制限

FW は生の CAN/UART ブリッジにはしない。host のスケジューリング遅延や切断が
トルク遮断を妨げないよう、デバイス制御ループと安全停止は基板上で完結させる。

## 基板ごとの能力

### cctl

3 つのアクチュエータスロットを提供する。スロット番号は機体軸ではなく、基板に
接続されるデバイスを表す。

| slot | backend | 指令・状態のネイティブ単位 |
|---|---|---|
| 0 | RobStride EL05 | rad |
| 1 | M3508 + C620 | motor deg |
| 2 | M3508 + C620（2台目） | motor deg |

モータID、制御周期、ドライバの速度・電流・温度上限は基板能力としてFWに保持する。
機体座標への換算、原点、可動域はhostが管理する。

### serial_svmd

STS3215 バスに対するトルク切替、位置指令、現在位置取得を提供する。
サーボID、目標位置、動作シーケンスは固定しない。

### svmd

4チャネルのPWMサーボ終端として、チャネルごとの目標パルス幅と有効状態を扱う。
全チャネルを同じ角度へ動かすような機体固有処理は持たない。

hostはcctlのFDCAN2ゲートウェイ経由でsvmdとserial_svmdへ指令する。serial_svmdは
USART2のASCIIも受けるが、これは基板単体で触るための口で、機体では使わない。
使用有無、ID、チャネル、可動域は機体プロファイルで決め、FWには保存しない。

## セッションと安全状態

DCMDは1chの符号付きDuty出力とENC1の累積カウントを提供する。Duty上限、ランプ、方向反転待ちと
通信断時のブレーキ停止をFWが処理し、hostが入力割当と運用Duty上限を指定する。
配線・CAN仕様は[board_dcmd.md](board_dcmd.md)を参照。

1. 電源投入時は SAFE とし、出力を有効にしない。
2. host は能力とプロトコルバージョンを確認する。
3. host は運用設定を適用し、基板の応答値を確認する。
4. 必要なスロットを有効化してから RUN へ遷移させる。
5. RUN 中はJOGによる速度指令またはHEARTBEATを継続する。
6. Watchdog 時間を超えて指令が途切れた場合、FWはSTOPへ遷移して出力を切る。

RUN中に有効なslotがモータからの応答を`feedback_timeout_ms`を超えて受け取れない場合、
FWはそのslotを無効化して`STATE`の`stale`で通知する。hostとの通信が生きていても
モータ側のCANが抜けたことを検出するための経路である。

接点入力は状態として報告するだけで、FWの状態遷移には影響しない。リミットへの
到達で何を止めるかはhostが決める。大会規定の非常停止は動力電源を直接切る配線で
成立させるものであり、この経路に依存しない。

制御ゲイン、デバイス保護上限、モータのCAN ID、制御周期、DCMDのDutyとランプ、svmdのパルス幅、
serial_svmdのサーボバスのボーレートは、hostから実行時に変更できる。
書き込み環境がない場所でも実機調整を終えられるようにするためである。仕様は
[device_protocol.md](device_protocol.md)の実行時パラメータを参照。

cctlはSAFE中に変更値をFlashへ保存し、他基板はRAMに保持する。
hostはPCの機体設定を正とし、接続時に値を適用・照合してから運転を許可する。

機体プロファイルの形式は[host_machine_profile.md](host_machine_profile.md)に定める。

## 互換性

通信プロトコルにはバージョンを持たせる。FWは未対応の指令や範囲外の値を黙って
採用しない。cctlの構文不正行や非有限の位置目標は破棄される。機体可動域はhostが
検証する。serial_svmdは
構文不正もERRで通知する。拒否した指令では現在の出力状態を変更しない。
hostのrθz操作はcctlのJOG対応能力、設定一致、最新応答、原点、中立入力を確認してからRUNを送る。
svmdは各CAN指令のバージョンを検証し、独立した能力照会やRUN指令は持たない。

プロトコルの仕様は [device_protocol.md](device_protocol.md) に定める。

## 実装上の規約

- CubeMX生成コードは初期化とコールバック接続だけに限定する。
- HAL非依存の構文解析、検証、状態遷移は各FWの `src/domain/` に置く。
- プロトコルの共通実装をFW間でリンクせず、仕様とテストベクタを共有する。
- 基板固有ドライバと機体固有ロジックを同じ型に混在させない。
- FWの変更後はクロスビルドに加え、切断、範囲外指令、起動直後を実機で確認する。

# host操作ガイド

hostが機体へのシリアル接続を一つだけ所有し、GUI・DualSense・ローカルAPIから操作する。
機体設定と座標換算はhost、周期制御と通信期限による出力停止はFWが担当する。

## 起動

リポジトリのルートで実行する。

```sh
cargo run --locked --manifest-path host/Cargo.toml --bin host -- --simulate
```

模擬接続は、設定応答、r・θ・zの位置応答、通信断、指令拒否を再現する。
干渉、負荷、モータの制動距離を再現する物理シミュレータではない。
実機では`--simulate`を外し、`--serial-device /dev/ttyACM0`を指定する。
`--headless`はGUIを開かず同じワーカーとAPIを起動する。

新しいhostの速度操作には、`DEVICE`に`jog=1`を返すcctl FWが必要。
FWのビルドは実機への書き込み・動作確認とは別の工程になる。

## 画面と基本操作

| 画面 | 内容 |
|---|---|
| 操縦 | r・θ・zとEEの状態、操縦入力、画面ジョグ、r・z自動ホーミング |
| 調整 | 「アーム」「EE」「基板」「設定ファイル」を切替。編集の適用・保存状態は上部に常時表示 |
| 診断 | 接続・基板受信を一覧し、「個別に動作確認」「STS3215の設定」「接続と再初期化」「通信ログ」を左側で切替 |
| 文書 | 配線ガイド、操作手順などのMarkdown文書 |

全画面の上部に画面切替、接続状態、運転再開・停止・ソフト緊停を固定表示する。
通常時は一行にまとめ、緊停・個別テスト・原点調整など、操作判断が必要な場合だけ説明を追加表示する。
個別テスト中は対象と出力状態を表示し、停止ボタンは「テスト出力解除」になる。
接続状態・応答経過・設定一致と操作結果は下部で確認できる。

通常時は操作者表示を強調しない。AIが操作権を取得している間だけ赤枠と「AI操作中」を
表示する。状態の閲覧だけでは赤枠にならない。

| DualSense | 操作 |
|---|---|
| 左スティック上下 | z速度 |
| 左スティック左右 | θ速度 |
| 右スティック上下 | r速度 |
| L1を保持 | 機体設定の低速操作率で動かす |
| 右スティック左右 | EE全体回転（標準割当） |
| 十字キー上／下 | 畳み軸を設定ファイルの一方／他方の端点へ移動 |
| 十字キー右／左 | 把持3本を設定ファイルの一方／他方の端点へ移動 |
| Createを1秒保持 | 停止中、現在のθを0°として採用し、r・zホーミング開始 |
| Options | ホーミング完了後、中立確認して運転再開 |
| PS | 停止・保持／ホーミング中断 |

### キーボード操作

GUIにフォーカスがある間に使用できる。画面右上の「キー操作 ?」からも一覧を開ける。

| キー | 操作 |
|---|---|
| Space | ソフト緊停。緊停中は解除するが、運転は再開しない |
| s | 停止・保持。個別テスト中は出力解除 |
| Esc | 入力欄の編集終了、未実行コマンドの取消。機体操作は行わない |
| 1 / 2 / 3 / 4 | 操縦 / 調整 / 診断 / 文書へ切替 |
| h / l、gT / gt | 前 / 次のタブ（端では循環） |
| j / k | 下 / 上へスクロール（長押し可） |
| Ctrl+d / Ctrl+u | 下 / 上へ半ページ移動 |
| gg / G | ページの先頭 / 末尾（gから続くキーは0.8秒以内） |
| ? | キー操作一覧を開閉 |

`:`でコマンド入力を開き、Enterで実行する。

| コマンド | 操作 |
|---|---|
| `:run` | 運転再開 |
| `:stop` | 停止・保持。個別テスト中は出力解除 |
| `:recover` | 出力停止のまま設定を再送・照合 |
| `:apply` | 調整画面の編集内容を適用 |
| `:w` | 調整画面の適用済み設定をファイルへ保存 |

文字・数値・コマンドの編集中は、文字入力を優先する。ただし、出力中のSpaceは
入力先を問わず緊停する。緊停中の入力欄ではSpaceで解除せず、空白として扱う。
解除はEscで編集を終了してからSpace、または解除ボタンで行う。
緊停キーの長押しでは解除しない。F1〜F4、F12、旧Ctrl系の運転・適用・保存キーは使わない。

### エラー後の再確認

エラーや設定不一致で操作できない場合は、出力を停止して「設定を再送して確認」を押す。
同じ操作は`:recover`、CLIでは操作権取得後の`hostctl recover --token <token>`から実行できる。
基板との通信が復旧していれば、出力停止のまま現在の設定を再送・照合し、過去のエラー表示をクリアする。
設定照合が再び失敗した場合は、そのエラーを表示する。

運転は自動再開しない。ソフト緊停やモータの異常・応答切れは解除しないため、
実際の異常が残っている軸は引き続き操作できない。
個別テストで異常が出た後は、出力ボタンから一度手を離してから再操作する。

### 停止と状態表示

全ページ上部に「運転中」「停止・保持」「出力停止」「ソフト緊停中」
「接続断 / 状態不明」を表示する。運転応答待ちや個別テストの出力中も区別する。
基板の出力状態とhostの操縦状態は異なり、「停止・保持」ではcctlのRUNを維持する。

ソフト緊停はcctlと、機体設定または個別テストで使用しているPWMサーボ・DCモータ・STS3215基板へ出力停止を送る。
保持の例外は設けない。AI操作権と待機中の要求を破棄し、緊停中は再取得できない。
人間がGUIで解除するまでAIから解除・再開できない。解除後も出力停止を維持する。
物理的な動力電源遮断は別系統。

「全出力停止」や緊停だけでは原点を無効化しない。位置が追跡できていれば、手で移動した
位置から再開できる。通信断、基板再起動、位置の不連続などで追跡を信用できなくなった場合は
原点確認が必要となる。

### 設定と文書

調整画面は、未適用の編集と適用中の設定の保存状態を別々に表示する。
適用・保存の前に明示的に停止する。個別テスト出力中の適用・保存も受け付けない。
適用時には出力を解除し、基板への設定反映後も自動再開しない。
編集中の内容が適用中の設定と異なる間は保存できない。先に適用するか、
「編集を戻す」で編集を破棄する。`:w`は編集内容を自動適用しない。

調整内の表示を切り替えても、未適用の編集と読込元・保存先は保持する。
「アーム」で軸を選ぶと、原点・速度・可動域・PID・位置応答を同じページに表示する。
「EE」では5機構の割当状況を一覧し、選択した機構の設定だけを編集する。
「基板」で基板別の制限値と通信周期を編集する。
「設定ファイル」で読込元・保存先とTOML本文を編集する。保存ボタンにマウスを重ねると保存先を確認できる。

折り畳み項目は初期状態で展開する。調整値には単位と説明を併記する。
「読込元・保存先」にパスを指定して「ファイルから読込」を押すと編集欄に読み込む。
保存先を変更して保存が成功すると、以後はそのパスを使用する。
操作結果は画面下部に表示し、長いメッセージはマウスを重ねて全文を確認できる。

診断上部にはcctlとの接続、設定一致、周辺基板の受信状況を常に表示する。
異常発生時は「異常ログを開く」から、ERRで絞り込んだ通信ログへ移動できる。
診断の「接続と再初期化」では実機・模擬接続の切替、再初期化、模擬障害の操作を行える。切替は停止中に行い、原点を再確認する。
「通信ログ」は独立した表示で、文字列による絞り込みができる。AI操作中の「通常操縦へ戻す」は停止・保持して操作権を解除する。

文書画面は`docs/`以下の`.md`を用途別に一覧化し、タイトルまたはファイル名で検索できる。
左側で文書を選ぶと、右側に見出し・表・リスト・コードブロックなどを描画する。
文書追加や編集後は「再読込」で反映する。Markdown間の相対リンクは同じ画面で開く。
Mermaidのコードブロックはソース表示となる。

### 個別テスト

診断の「個別テスト」から個別テストモードに入ると、通常操縦を停止し、DualSense・通常の画面ジョグ・
AI操作を無効化する。出力対象は1つ。基板・チャネル・方式を変更すると前の出力を解除する。
モード終了時も出力を解除し、通常操縦は再開操作を待つ。

| 対象 | 操作・単位 |
|---|---|
| cctl slot 0..2 | 位置指定で保持、または押下中だけ速度出力。slot 0/2はrad、slot 1はモータ角deg |
| PWMサーボ ch 0..3 | パルス幅µsを指定し保持 |
| STS3215 ID 1..253 | 位置0..4095を指定し保持。速度100、加速度10で送信 |
| DCモータ ch 0 | 押下中だけ-100..100‰（最大10%）を出力 |

cctlの速度テスト上限は機体設定の通常速度に低速操作率を掛け、モータ単位へ換算した値。
位置テストは原点採用済みの軸だけ使用でき、hostの機体座標と可動域で指定する。
対応する基板はcctlのUSB1本とFDCAN2経由で接続する。周辺基板のアドレスは0を使用する。

上部タブや診断内のサブタブを切り替えると、位置保持を含む出力を解除し、個別テストモードを終了する。
クリック・数字キー・Vimのタブ移動は同じ動作となる。同じタブの再選択では終了しない。
別アプリへの切替では位置保持は継続する。「テスト出力解除」・`s`・`:stop`でも出力を解除できる。
押下中だけの出力は、ボタンを離す、フォーカスを失う、入力更新が150ms途切れると解除する。
対象基板の応答喪失や指令拒否でも停止し、自動では再開しない。押下中の異常停止後は、
ボタンを離してから押し直す。位置指定は改めて移動ボタンをクリックする。
どちらも対象の応答・異常を再確認してから出力する。

cctl接点と、設定・選択した周辺基板のDCエンコーダ・接点、STS基板接点、選択したSTSサーボの実測値を受信表示する。
センサ読取りだけでは出力を有効化しない。模擬接続でも同じGUI・要求経路を使用できるが、
負荷・干渉・実際の制動距離は再現しない。

### 操縦の開始

認識対象はDualSense / DualSense Edge。複数候補がある場合は自動選択せず、使用する
1台を接続する。操縦画面はr・θ・z、操縦入力、EE、r・z自動ホーミングを同時に表示する。
各アーム軸の「単体テスト」は、その軸を選択した状態で診断画面を開く。
「アーム設定を開く」「EE設定を開く」は、対応する調整項目へ直接移動する。
停止中に「DualSense」と「画面操作」を選択できる。
DualSense接続中は、操縦画面に左右スティック、L2・R2、押下中のボタンと、
機体設定の向き・低速・デッドゾーンを反映した操作要求を20Hzで表示する。
停止中やAI・画面操作を選択中も入力値は確認できるが、「モニタのみ」と表示して機体への反映と区別する。
画面操作は実機・模擬接続ともに利用でき、運転再開後に各軸の±ボタンを押している間だけ
設定した低速操作率で動く。ボタンを離す、ページを切り替える、ウィンドウからフォーカスを外すと
入力が0になる。更新が150ms途切れた場合も0になる。模擬接続では画面操作を初期選択する。

1. 設定の一致確認が終わるまで待つ。
2. 調整画面で原点を採用する。原点まで移動する場合は原点調整モードで低速操作する。
3. 軸の正方向、原点、暫定可動域、干渉を実機で確認する。
4. 原点調整モードを解除し、スティックを中立にして運転再開する。

「停止・保持」は停止時の実測座標を目標として固定し、位置保持を続ける。通常運転中も
スティックが中立へ入った時点の座標を固定する。診断の「全出力停止」「SAFE」は
出力を切る。物理非常停止は別系統で動力電源を切る。
通信断、DualSense操作中のコントローラ切断、基板や原点の異常では出力停止となり、自動再開しない。

## 起動済みhostへの接続

```sh
cargo build --locked --manifest-path host/Cargo.toml --bins
host/target/debug/hostctl status
host/target/debug/hostctl config
host/target/debug/hostctl claim
```

`claim`が返す`token`を以後の変更操作に渡す。操作権は最後の変更操作または
`heartbeat`から30秒で失効する。例の`TOKEN`は取得した値に置き換える。

```sh
host/target/debug/hostctl origin --token TOKEN --axis r
host/target/debug/hostctl origin --token TOKEN --axis theta
host/target/debug/hostctl origin --token TOKEN --axis z
host/target/debug/hostctl run --token TOKEN
host/target/debug/hostctl status
host/target/debug/hostctl input --token TOKEN --axis r --value 0.2 --seconds 1
host/target/debug/hostctl stop
host/target/debug/hostctl release --token TOKEN
```

`input`は-1..1の正規化入力。`--seconds`は0..30秒で、50ms周期に再送し最後に0へ戻す。
各軸の入力が150ms途切れると、その軸の入力が0になる。上位の通信失敗時にはFWのWatchdogも出力を停止する。
`run`の受付成功は基板の運転確認ではない。`status`の`running`と`board_mode`で確認する。

GUIとAPIは同じ操作受付を使う。AI操作中の通常操縦は停止し、`stop`はtokenなしでも
受け付ける。AIが解放・失効しても通常操縦は再開操作を待つ。

| action | 追加引数 | 用途 |
|---|---|---|
| `status` / `config` | なし | 状態・通信ログ / 現在の機体設定を取得 |
| `claim` | なし | 停止・保持してAI操作権を取得 |
| `heartbeat` / `release` | `--token` | 操作権を更新 / 解放 |
| `run` / `stop` | `run`のみ`--token` | 運転開始 / 停止・保持 |
| `safe` / `cut` | `--token` | SAFE / 全出力停止。位置追跡が続けば原点維持 |
| `estop` | なし | 全出力停止・緊停状態を固定。GUIで人間が解除 |
| `origin` | `--token --axis` | 停止中の最新位置を原点として採用 |
| `adjustment` | `--token --flag true/false` | 原点調整モード |
| `input` | `--token --axis --value [--seconds]` | 速度入力 |
| `apply` | `--token --file path.toml` | 機体設定を一時適用 |
| `save` | `--token [--text 保存先パス]` | 適用中の機体設定を保存。保存先省略時は現在の設定ファイル |
| `connection` | `--token --file connection.toml` | `serial_device`と`baud_rate`、任意の`simulate`を指定して再接続 |
| `reinit` | `--token --axis` | モータの制御モードを再設定、原点無効化 |
| `fault` | `--token --text <障害名>` | 模擬接続の障害注入。通常は診断画面を使用し、詳細な一覧は`host/src/transport/simulator.rs`を参照 |

APIは同じOSユーザだけが接続できるUnixソケット。既定は
`$XDG_RUNTIME_DIR/catchrobo-host.sock`、未設定時は`$HOME/.cache/catchrobo/host.sock`。
両プログラムの`--socket`で変更できる。ネットワークへは公開しない。

通信形式は、UTF-8 TOML本文の長さを4 byteのbig endianで前置する。1接続1要求、本文上限
128KiB。要求の構造は`host/src/application/command.rs`の`Request`、応答は`Reply`。
`ok`は受付結果、`data`は状態または設定のTOML文字列。状態取得は操作権不要。

## ソフトウェアでの確認

```sh
cargo test --locked --offline --manifest-path host/Cargo.toml
cmake --build tests/build
ctest --test-dir tests/build --output-on-failure
```

結合テストは別プロセスの模擬hostへ実際のソケットで接続し、操作権、入力期限切れ、
停止・保持と全出力停止、RUN応答待ち中の停止、再接続、原点の再確認、異常復旧、
運転中の設定変更拒否、一時適用と保存を確認する。通信無音時の基板watchdogと、
動作モード・有効軸・stale・異常bit・再起動の受信時停止も対象に含む。

## セッティングから競技開始

起動時は「1 準備・操縦」のセッティング画面を表示する。
設置・固定、接続と設定の照合、原点設定、開始姿勢への配置の順で準備する。
原点設定は同じ画面から行う。原点設定の終了位置と競技開始姿勢は別であり、
開始姿勢への配置は操作者が行う。

配置後に「配置を終えて停止・保持」を押し、実際の姿勢を確認する。
この停止操作は既存の通常停止であり、EE出力を解除する。
固定・ケーブル・シューティングエリアとボックスからの離隔・全員の退避を確認し、
「準備完了 → 開始待ち」を押す。接続、設定、原点、入力中立、テスト終了などの
条件が不足している場合は画面に理由を表示する。

開始待ちへの切替自体は駆動指令を送らず、現在の保持状態を維持する。
GUI、パッド、APIからの通常操縦・原点設定・設定変更・個別テストをワーカーで拒否する。
会場の開始合図後、スティックとボタンを離した状態で「合図確認 · 競技開始」を押す。
既存のRUN応答確認を経て操縦へ移り、自動的な原点設定や開始姿勢への移動は行わない。

停止・緊停、または検出した機体状態の喪失で開始待ちを取り消す。
解除・通信復旧だけでは準備完了へ戻らない。「準備へ戻って再確認」からやり直す。
待機中の準備再開は審判の許可に従う。準備未完了でセッティングが終了した場合は、
競技開始後にリトライを申告する。

物理非常停止の直接検出と、電源断後の姿勢・座標の保証はこのフローには含まれない。
ソフト緊停を物理非常停止の代わりに使わない。時間計測は行わない。

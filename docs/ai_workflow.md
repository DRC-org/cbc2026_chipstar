# AI エージェントの作業ルール

このリポジトリで AI エージェントがコードを変更する際の進め方。

## 作業の分割

1 コミット = 1 つの意味のある変更にする。目的の異なる変更を 1 コミットに混ぜない。

分割の境界:

- **プロジェクト単位**で分ける（`cctl` / `serial_svmd` / `svmd` / `ros2` / `host`）
- **機能追加と、リファクタ・ファイル移動を分ける**。移動と中身の変更を同時に行うと差分が読めなくなる
- **CubeMX 再生成による自動生成コードの変更と、手書きコードの変更を分ける**
- **ドキュメントのみの変更は独立させる**

一方だけではビルドが通らない、あるいは分けると不整合な状態が履歴に残る場合は、
まとめて 1 コミットにしてよい。まとめた理由を説明できることが条件。

## コミット

作業単位が 1 つ終わるたびにコミットする。すべての作業を終えてから 1 回にまとめない。

コミット前に、対象プロジェクトのビルドが通ることを確認する。

### メッセージ

Conventional Commits の形式で、**`<type>: <説明>` の 1 行のみ**。本文は原則付けない。

説明は日本語で、何をしたかが分かる粒度にする。

```
feat: コントローラで rθ操作を実装
chore: clang-tidy を追加
```

| type | 用途 |
|---|---|
| `feat` | 機能追加 |
| `fix` | バグ修正 |
| `refactor` | 挙動を変えない構造変更 |
| `docs` | ドキュメントのみの変更 |
| `chore` | ビルド設定・ツール・依存関係 |
| `test` | テストの追加・修正 |

### 付けないもの

- `Co-Authored-by` トレーラ
- 生成ツール名、セッション URL、その他の署名・トレーラ

コミットメッセージは `<type>: <説明>` の 1 行で終わらせる。
